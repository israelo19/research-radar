## Read today

**[MCP Tool Poisoning in Agentic AI Frameworks: A Cross-Framework Measurement Study](https://arxiv.org/abs/2611.03555)**  
MCP and tool security · score 10/10 · arxiv  
A cross-framework measurement study of MCP tool poisoning with real tool execution. It builds a 25-class taxonomy and a 9,720-cell susceptibility matrix across 12 frameworks, 18 models, and 45 attack scenarios, finding a 22.9% overall attack success rate.  
Why it matters to you: It directly measures how attacker-controlled MCP tool descriptions, schemas, and responses can cause real tool calls, endpoint contact, and secret exfiltration in agentic frameworks.  
Read it asking: Which parts of the attack success rate are driven by model behavior versus framework plumbing, and what does that imply for where defenses should be placed?

**[Where Does MCP Security End? A Three-Tier Mitigation Mapping Framework for the OWASP MCP Top 10](https://arxiv.org/abs/2611.02611)**  
MCP and tool security · score 9/10 · arxiv  
This paper proposes a framework for mapping OWASP MCP Top 10 vulnerabilities to server, gateway, or protocol tiers. It validates the framework on an MCP server and identifies architectural limits that prevent full mitigation at the server layer.  
Why it matters to you: It directly addresses MCP security, prompt injection, confused deputy risks, and where defenses can or cannot be applied in the MCP stack.  
Read it asking: Which MCP vulnerabilities are truly fixable at the server layer, and which require gateway or protocol-level changes?

**[Right Tool, Wrong Parameters: Defending LLM Agents Against Parameter Poisoning](https://arxiv.org/abs/2611.04673)**  
MCP and tool security · score 8/10 · arxiv  
The paper studies parameter poisoning, an indirect prompt injection attack where an LLM agent performs the intended tool call but with attacker-influenced arguments. It proposes AuthorityFlow, a defense that checks whether the information source for each tool parameter is trusted under the user's task, and introduces FactAuthBench for evaluation.  
Why it matters to you: It directly addresses prompt injection through agent tool use and malicious manipulation of tool parameters, which is central to MCP and tool security.  
Read it asking: How robust is the trust-hierarchy approach when the user query is ambiguous or when a low-trust field legitimately influences a tool parameter?
