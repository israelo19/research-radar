# Research radar, 2026-11-10

## Read today

**[Scaling Adaptive Prompt Injection Attacks with Agent Swarms](https://arxiv.org/abs/2611.11861)**  
MCP and tool security · score 9/10 · arxiv  
The paper studies adaptive prompt injection attacks against AI agents using agent swarms and a synthetic evaluation dataset. It shows that more capable agentic attackers can still trick models into following malicious instructions in tool output, even when models appear robust on public benchmarks.  
Why it matters to you: It directly addresses prompt injection through tool output and the limits of current agent defenses, which is central to MCP and tool security.  
Read it asking: How much of the reported success comes from the attacker's adaptive search versus weaknesses in the model's instruction hierarchy?

**[Treating the Model as an Untrusted Component: Deterministic Policy Enforcement, Human Approval and Taint Tracking Against Prompt Injection in Tool-Using Agents, with Validation on Open-Weights Models](https://arxiv.org/abs/2611.11571)**  
MCP and tool security · score 9/10 · arxiv  
The paper studies prompt injection in tool-using LLM agents by comparing in-prompt defenses with deterministic external monitors, human approval, and taint tracking. It reports real-model results on Qwen2.5-1.5B and Qwen2.5-7B plus simulation results showing adaptive attackers can defeat guardrail stacks unless a deterministic monitor and approval budget are used.  
Why it matters to you: It directly addresses prompt injection through tool output and tool-call enforcement in agent tools.  
Read it asking: Do the deterministic monitors and taint-tracking results transfer to MCP-style dynamic tool servers, or are they tied to the fixed 12-tool benchmark?

**[Coding Agents in KVM: Practical Containment and User Control with Limited Resources](https://arxiv.org/abs/2611.12823)**  
Agent privilege escalation · score 8/10 · arxiv  
The paper presents KVM-Agent, an open-source system that runs coding agents inside disposable Ubuntu VMs to limit the damage from overly privileged agent access. It focuses on practical containment, user control, and avoiding vendor lock-in while still allowing agents broad authority inside the VM.  
Why it matters to you: It is directly about sandboxing and runtime containment for coding agents, which is central to agent privilege escalation.  
Read it asking: What residual escape or exfiltration paths remain when the agent can access secrets and network inside the VM?
