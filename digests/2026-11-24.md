## Read today

**[ParseGap: Testing What Coding Agents Authorize and What Shells Execute](https://arxiv.org/abs/2611.29546)**  
Agent privilege escalation · score 10/10 · arxiv  
The paper shows coding agents can approve shell commands that their policy checker interprets safely but Bash executes with policy-violating effects, and proposes ShellPlan to compile a restricted Bash subset into a typed plan executed without a shell. It tests eight production agents and reports 17 root causes plus a defense with strong attack and completion results.  
Why it matters to you: It directly studies how coding-agent permission gates and OS sandboxes can be bypassed through parse/execution divergence, which is core to agent privilege escalation.  
Read it asking: Which of the identified divergence boundaries are most likely to transfer to MCP tool calls or other agent tool interfaces, and what does the single-interpretation dispatch assumption require in practice?

**[Conartist: Adaptive Agentic Red-Teaming of Computer-Using Agents against Multi-Step Prompt Injection](https://arxiv.org/abs/2611.29977)**  
Agent privilege escalation · score 9/10 · arxiv  
The paper introduces Conartist, an adaptive prompt-injection framework that attacks computer-using agents by making malicious steps look consistent with user goals and by exploiting the agents' own risk-auditing process. It reports high attack success rates on tool-use and GUI benchmarks and identifies exploitable patterns in a popular agent.  
Why it matters to you: It directly targets computer-use agent permission and security boundaries, showing how runtime checks and auditing can be manipulated to enable unauthorized actions.  
Read it asking: Which parts of the attack depend on the agent's auditing feedback, and what minimal runtime policy changes would break the adaptive attack loop?

**[AgentBouncer: Defending Software Engineering Agents via Dynamic System-Call Mediation](https://arxiv.org/abs/2611.30621)**  
Agent privilege escalation · score 9/10 · arxiv  
AgentBouncer is a runtime enforcement system for software engineering agents that mediates and can deny system calls triggered by tool calls, using an LLM arbiter to judge necessity and safety. It evaluates 340 attacks plus benign SWE-bench tasks and reports reducing attack success from 99.41% to 10.59% while preserving task success.  
Why it matters to you: It directly addresses coding-agent privilege escalation and malicious tool/supply-chain actions by adding runtime policy enforcement at the system-call level.  
Read it asking: What are the failure modes of the LLM arbiter when an attack disguises a malicious system call as necessary for the task?
